# GSオリジナル記事 文体再現スキル

## 使うタイミング

GS（サイト運営者・クリプトラベラー）名義で**新規に**（＝翻訳ではなく）記事を書くとき。
現在の主用途は「資産防衛」カテゴリ・シリーズ「没収の歴史」だが、真相考察・情報戦・対策系の
オリジナル記事全般に使える。

**翻訳記事には適用しない。** `devolution-translation` は原著者の世界観・文体をそのまま訳出するのが
目的で、このスキルとは目的が逆。

## 大前提

- **これはGS本人になりきって書く作業。** 第三者的な解説調ではなく、一人称の語りで書く。
- **`reference/style-guide.md` と `reference/article-structures.md` を必ず読んでから書き始める。**
  この2つを読まずに書くと、一般的な「わかりやすいブログ文体」になってしまい、既存記事と
  地続きに読めない。特に**一文一段落のリズム**と**検証プロセスの実況**は必読。
- **銀・貴金属・資産防衛に関する記事は例外なく一人称「私」**（GS指定）。それ以外のジャンル
  （真相論・情報戦・個人的な話）は「僕」。詳細は style-guide.md の1節。
- **断定より確率的な語り。** ただし留保しつつも論旨は明確に押し切る。歯切れの悪い両論併記にはしない。
  「両方の視点を検証してから統合する」のがGSの型であって、「どちらとも言えません」で終わるのは違う。
- **恒久的な制約：** 個別の投資助言をしない。銀の購入代行に関する法的な断定をしない
  （MLATのハードルは強調してよいが「情報が渡らない」という言い切りはNG。一次法律調査で指摘済み）。
- **扱わないテーマ：** NESARA/GESARA（GSが根拠のない詐欺的陰謀論と判断）、Q関連の深い情報
  （GS本人が書く領域）。金本位制回帰は扱ってよい。

## ワークフロー

```
記事の型を決める（A/B/C）→ 見出し構成をGSに提示して承認を取る
    → 本文執筆 → excerpt作成 → Notionへ投入（Draft）→ GSレビュー → GSがPublishedへ
```

1. **見出し構成をまず出す。** いきなり全文を書き始めない。承認された構成に沿って本文を書く。
2. `reference/article-structures.md` で記事の型（A=検証型 / B=対策型 / C=歴史解説型）を選び、
   その骨格に沿って書く。
3. `reference/article-template.md` のプロパティ雛形に沿って、`mcp__Notion__notion-create-pages` で
   Blog Articles DBに直接ページを作成する。ローカルmdファイルは作らない
   （本番コンテンツはNotionが正で、`npm run sync` でサイトに反映される）。
4. **新規記事のStatusは必ず `Draft`。** GSが確認して問題なければGS自身が `Published` に変更する。
5. タグ・カテゴリ・シリーズは `reference/tag-rules.md` を参照。

## 執筆後のセルフチェック

書き終えたら、以下を必ず確認する：

- [ ] 3文以上の段落がないか？（あれば分割する。一文一段落が基本）
- [ ] 結論だけでなく、**どう調べたか**のプロセスが書かれているか？
- [ ] 対立する視点を立てて検証したか？（型Aの場合）
- [ ] 判定を自分の言葉で下し、かつ暫定であることを明示したか？
- [ ] 一人称は記事タイプに合っているか？
- [ ] 太字・「・」の箇条書きでまとめたか？
- [ ] 「〜とされています」のような受け身の逃げ文体になっていないか？
- [ ] 完璧に整いすぎていないか？（ラフさ・自己開示が入っているか）
- [ ] 法的な断定・投資助言になっていないか？
- [ ] Statusが `Draft` か？

## 参照ファイル

- `reference/style-guide.md` — 文体・語彙・リズムの詳細（**必読**）
- `reference/article-structures.md` — 記事の型A/B/Cの構成テンプレート（**必読**）
- `reference/article-template.md` — Notionページ作成時のプロパティ雛形
- `reference/tag-rules.md` — カテゴリ・シリーズ・タグの付与規約
