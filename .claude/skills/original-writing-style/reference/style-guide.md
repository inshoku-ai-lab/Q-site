# 文体ガイド

4本のオリジナル記事（没収対策記事、なぜ今銀なのか、支配層の罠、偽ユダヤ偽イルミナティ）から
抽出した、GSの文体的特徴。書く前に必ず読み返すこと。

## 1. 一人称・語りかけ

- 経済・資産防衛ジャンルでは **「私」**。Qやスピリチュアル寄りのよりカジュアルな記事では「僕」の
  こともあるが、**銀・資産防衛シリーズは「私」で統一する**（没収対策記事の実例に合わせる）。
- 読者は「皆さん」「あなた」と直接呼びかける。地の文がしばしば読者への語りかけの形を取る。
  例：「皆さんは資産防衛についてはどのようにお考えでしょうか？」
- 記事冒頭で軽い挨拶から入ることがある：「皆さんこんにちは、クリプトラベラーです。」
  → 続けて時事的な枕（「激動の時代をいかがお過ごしでしょうか？」）→ 問いかけ → 本題へ、という導入の型。

## 2. 文の長さ・リズム（最重要）

**ほぼ一文一段落。** 複文・重文を避け、短い単文を積み重ねる。改行が非常に多い。
これがGSの文体で一番目立つ特徴であり、一般的なAIが書く「3〜5文で1段落」という
まとまり方とは対照的。書くときはこの粒度を強く意識すること。

悪い例（AIがやりがちな段落構成）：
> 政府による貴金属没収は歴史上何度も起きており、1933年の米国大統領令6102号や1934年の
> 大統領令6814号がその代表例である。これらの命令により、多くの市民が金銀を手放すことを
> 余儀なくされた。

GSの文体に寄せた例：
> 過去においては貴金属没収政策は１９３０年代の大不況の中で米国のルーズベルト政権の
> 大統領令として施行されました。
>
> この「買取り」の時には、それ相応の価格で買い取られているので、買取時だけを見れば
> 没収というほどの酷いことではありません。
>
> 公平な強制交換ともいえます。
>
> ですが、買取り完了直後に金互換レートが４０％上がっているので、実質的には４０％を
> 政府に盗まれたといっても過言ではないでしょう。

## 3. 修辞疑問文を多用する

読者に問いを投げてから答える、という運び方が非常に多い。

- 「〜でしょうか？」を段落の締めに使う
- 短い疑問を連打することがある：「混乱してますか？」「なぜでしょう？？？」
- 問い→間（改行）→答え、のテンポ

## 4. ヘッジ表現と言い切りのバランス

断定は避けるが、歯切れは悪くしない。以下のフレーズを積極的に使う：

- 「〜でしょう」「〜と言えるでしょう」
- 「〜かもしれません」「〜と考えられます」
- 「〜のではないでしょうか」
- 「私は〜と考えています」「〜だと思っています」「僕の理解では」
- メタ的な留保：「これは僕が即興で考えた例なので」「〜と語れるほどの知識は持っていませんが」

これらは弱さの表現ではなく、**言い切れないグレーな領域を扱っていることの誠実さの表明**として機能する。
特に銀の購入代行に関する記事では、法律・規制の話は必ずこのトーンで書く（断定表現は誤りのリスクが
高いだけでなく、この文体からも外れる）。

## 5. 見出し構成

- `##` で細かく章立てする。1見出しあたりの分量は短め（数百字程度のことも多い）、長々と
  1つの見出しの下で書き続けない。
- 対策・方法を列挙する記事では「対策方法１」「対策方法２」…という通し番号見出しに、
  太字の短いスローガンを添えるパターンがある：
  ```
  ## 対策方法１

  **「検証できるかどうか検証する」**

  検証の第一歩は、その情報が検証できるものなのかどうかを検証すると言うことです。
  ```
- 記事の終盤に `## まとめ` を置き、`・` の箇条書きで論点を再整理することがある。

## 6. 具体例・たとえ話

抽象的な仕組みを説明するとき、身近な比喩に置き換える技法をよく使う
（例：情報の見分け方を「賭けビリヤードで上級者が初心者を装って中級者を罠にかける」話に例える）。
説明が抽象的になりそうなときは、たとえ話を1つ挟めないか考える。

## 7. 語彙・世界観フレーム

以下の語彙が地の文に自然に登場する。経済記事でも陰謀論記事でも共通の世界観：

`支配層` / `資産防衛` / `情報戦` / `覚醒` / `両建て`（複数のシナリオに同時に備える、という頻出概念）

強調・つなぎの副詞：`ズバリ` `はっきり言って` `残念ながら` `正直` `もちろん`

## 8. 引用・外部リンクの形式

- 外部記事・Wikipedia・政府文書へのリンクは `[blogcard url="https://..."]` という
  独自ショートコードでカード表示する（`ArticleBody.astro` がこれをパースしてカードに変換する）。
- 政府文書やWikipediaの記述を引くときは、`>` のブロッククォートで該当箇所を短く引用してから、
  地の文で解説を続ける。
- 画像は本文中に `![](画像パス)` でキャプションなしに挟むことが多い。

## 9. 結び

以下のいずれかのパターンで締めることが多い：

- 「最後までお読みいただきまして、ありがとうございました。」という定型句
- 「〜な方は、ぜひこちらのお問合せからご連絡ください。」のような行動喚起
  （銀の購入代行記事では `/silver` ページへのリンクにする）
- 「今回の記事は宣伝要素が強いですが、非常時に役に立つ重要な情報を提供できたのでは無いかと
  思っています。」のような、宣伝であることを自覚しつつ価値を再主張する一言

## 10. やってはいけないこと（AIが陥りがちな失敗）

- 3〜5文をひとまとめにした「教科書的な段落」を書かない。1〜2文で改行する。
- 「〜とされています」「〜と言われています」のような、責任の所在をぼかす第三者的な受け身文体に
  流れない。GSは自分の意見として語る（ヘッジはするが、主語は常に「私」）。
- 学術論文のような脚注・出典表記（[1]など）を使わない。`[blogcard url="..."]`かブロッククォートで。
- 長い1文に情報を詰め込まない。情報は複数の短文に分けて、間（改行）でリズムを作る。
- 銀の購入代行に関する記事で、法的な断定（「〜は不可能です」「絶対に安全です」）をしない。
  MLATの壁やハードルの高さは強調してよいが、「情報が絶対に渡らない」という言い切りは避ける
  （この誤りは一次法律調査で既に指摘済み、`ARCHIVE-FOR-BUSINESS-OS.md` 第6節参照）。
