# 放浪記 → The Vagabond Chronicles 英訳スキル

クリプトラベラー氏の自伝的紀行シリーズ「放浪記」（Notion "Blog Articles" DB, Series =「放浪記」、
Episode 0〜521、全522本、約81万字）を英訳する。英題は **The Vagabond Chronicles**。

---

## 0. 大前提（必ず守る）

- **書き手の声を消さない。** ドラッグ、性、宗教批判、貧困、反権威、下ネタ、自嘲——原文が率直に
  書いていることは率直に訳す。婉曲化・道徳的な注釈の追加・「とされる」による距離取りは**禁止**。
  これは事実主張の代弁ではなく「原文の忠実な翻訳」である。
- **過剰なアメリカ化も同じくらい深刻な失敗。** 目標は「アメリカ人が書いた英語」ではなく、
  **「アメリカ人がスラスラ読めるが、語っているのは紛れもなく日本人の彼」**。
  日本人が世界を放浪する視点そのものがこの作品の価値であり、それを消してはいけない。
  参照すべき到達点は村上春樹作品の英訳（Jay Rubin 等）。
- **英語の自然さの判定責任は Claude が持つ。** ユーザーは英語の自然さを判定しない前提で運用する。
  したがってユーザーへ出すのは**日本語で検証できる成果物**（逆翻訳＋判断メモ）であり、
  英語品質はパス③のブラインド査読ゲートを通すことで担保する。§5 を必ず読むこと。
- **日本語記事は改変しない。** 英訳は既存ページの上書きではなく、常に**新規の英語ページ**を作る。
- **前後記事リンクは本文に入れない。** 英語版の本文末尾にナビゲーションリンクを書かない。
  サイト側が生成する。
  > **注意**：日本語版の Notion ページからの削除（`npm run strip-nav-links -- --apply`）は
  > **まだ実行されていない**（NOTION_TOKEN 待ち）。未実行のうちは、Notion から取得した
  > 原文にナビ行が残っているので、**翻訳の入力にする前に必ず自分で除去する**こと。
  > 判定には `scripts/lib/nav-links.mjs` の `isNavOnlyText()` と同じ基準を使う。
- **用語・人名は `reference/glossary.md` に統一。** 新出語は必ず追記してから使う。
  522話にまたがるので、Episode 103 と Episode 400 で同じ人物の綴りが変わる事故を防ぐ。

---

## 1. 全体の流れ

```
【Phase 0】声の確定（最初に1回だけ・ここが全体品質を決める）
  アンカー5本を全力翻訳 → ユーザー承認 → voice-bible.md を確定

【Phase 1】量産（アーク単位でループ／全47アーク）
  アーク文脈カード作成
   → 各話：① 翻訳 → ② 対訳監査 → ③ ブラインド査読 → ④ 統合編集 → ⑤ 機械QA
   → アーク通し整合パス
   → 日本語レポート提出（ユーザーが忠実性を検証）
   → Notion へ英語ページ作成
```

**Phase 0 を飛ばして Phase 1 に入ってはいけない。** 声が決まっていない状態で量産すると、
522話ぶんの手戻りが発生する。

---

## 2. Phase 0 — 声の確定（最初に1回）

### 2-1. アンカー記事5本

作品の振れ幅をカバーする5本を選ぶ。デフォルトは以下：

| Ep | タイトル | なぜアンカーか |
|---|---|---|
| 000 | 世界中を２０年以上放浪し続けている話 | 読者への自己紹介。宣言的・熱量が高い |
| 003 | エホバの証人の家庭で育つ話１ | 幼少期・宗教・痛みを扱う静かな語り |
| 017 | 宗教、高校、家庭、日本から脱出し、ペルーに向かう話 | 転機。感情の山場 |
| 103 | ゴアに出会う話６ | ドラッグ・パーティー・コメディ。最も訳が難しい |
| 450 | 北アルプスの山小屋で働く話９ | 後期の落ち着いた筆致・労働の描写 |

### 2-2. 手順

1. 各アンカーを **2案** 独立に翻訳する（案Aは原文の語順・リズム寄り、案Bは英語の自然さ寄り）。
2. 2案を並べ、段落単位で優劣を判定して最良版を1本に統合する。
3. ユーザーに提出する際は **日本語で「どこをどう寄せたか」を説明**する（§5-2 の形式）。
4. 承認後、**確定した5本から実例を抜き出して `reference/voice-bible.md` を書き換える**。
   汎用的な翻訳論ではなく、**この作品の実際の Before/After** でルールを書くこと。

## 3. Phase 1 — 1話あたりの4パス

各パスは**役割を厳密に分ける**。1つのパスに2つの目的を持たせない。

### ① 翻訳（Translate）

入力：日本語原文＋`voice-bible.md`＋`glossary.md`＋アーク文脈カード
出力：英語ドラフト

- 語ではなく **意味とリズム**を訳す。
- 1文＝1段落の改行リズムは**原則保つ**（著者の文体であり、モバイルで読みやすい）。
  ただし英語として接続が必要な2文は結合してよい。
- 会員限定マーカーの位置を厳守（§4-3）。

### ② 対訳監査（Bilingual Audit）

入力：日本語原文 ＋ 英語ドラフト（**両方見る**）
出力：**指摘リストのみ。書き換えはしない**

チェック項目：欠落した節・文・段落／原文にない追加／誤訳／ニュアンスのズレ（特に敬語・自嘲・
皮肉）／数字・固有名詞・金額の取り違え／会員限定マーカーの位置ズレ。

各指摘は `重大度(P1/P2/P3) | 原文該当箇所 | 訳文該当箇所 | 何が問題か` の形式。

### ③ ブラインド査読（Blind Native-Reader Review）★最重要

入力：**英語ドラフトのみ。日本語を一切見せない。**
出力：**指摘リストのみ**

> **なぜブラインドか：** 原文を見た査読者は、ぎこちない英語を見ても
> 「日本語がこうだから仕方ない」と無意識に納得してしまい、translationese を検出できなくなる。
> 日本語を遮断して初めて「これは訳文くさい」が拾える。**②と③は目的が正反対なので、
> 絶対に同じパスで実行してはいけない。**

**実装上の必須条件**：このパスは必ず**サブエージェント**として起動し、プロンプトには
英語本文だけを入れる。日本語原文・原文ファイルパス・「これは翻訳である」という事実の
いずれも渡さない。査読者には「アメリカ人の一般読者としてこの回想録を読む」と指示する。

判定区分：
- **P1**：訳文くさい／意味が取れない／英語として誤り。**1件でも残っていたら公開不可。**
- **P2**：意味は通るが硬い・冗長・リズムが悪い。
- **P3**：好みの問題。

具体的なプロンプト文面は `reference/review-prompts.md` を使う。

### ④ 統合編集（Reconcile）

入力：日本語原文 ＋ ドラフト ＋ ②の指摘 ＋ ③の指摘
出力：最終稿

- **決定権はこのパスだけが持つ。②③は助言に過ぎない。**
- ③の自然さ修正は、②の正確性を壊さない範囲で採用する。両立しない場合は
  **意味の正確性を優先し、別の言い回しで自然さを回復する**（どちらかを諦めない）。
- 採用しなかった指摘は理由を1行残す。

### ⑤ ブラインド再査読ゲート

④の結果に対し、**新しいサブエージェント**（前のドラフトを見ていない）で③を再実行する。
**P1 がゼロになるまでループ**。最大3周。3周で収束しない場合は、その段落を全面的に書き直す。

> 同じ査読者に再査読させてはいけない。一度読んだ査読者は自分の指摘が反映されたかを見てしまい、
> 新鮮な読者としての判定ができなくなる。

### ⑥ 機械QA

```bash
python3 .claude/skills/hourouki-translation/scripts/qa_check.py <英語mdファイル> --source <日本語mdファイル>
```

検出項目：語数比の逸脱（段落落としの検出）／段落数の不一致／日本語文字の残留／
会員限定マーカーの有無と位置／ナビリンクの混入（あってはいけない）／数字・金額の不一致／
用語集違反／translationese ブラックリスト／フロントマターの欠落。

## 4. 出力仕様

詳細は `reference/output-spec.md`。要点：

### 4-1. 作業ファイル（リポジトリ）

`migration/posts-en/<NNN>-<slug>.md` に YAML フロントマター付きで書く。
**リポジトリを翻訳作業の正本とする**（git で差分・履歴・レビューができ、機械QAが効く）。
Notion は公開先であり、承認後に転記する。

### 4-2. Notion（公開先）

**日本語記事は一切変更しない。** 英語版は既存の日本語記事とは別の新規ページとして作る。

同じ "Blog Articles" DB に英語ページを新規作成する：

- `Lang` プロパティ（select: `JA` / `EN`）を新設し、英語ページは `EN`。既存日本語ページは `JA`。
- `Episode #` は日本語版と**同じ番号**（対応付けのため）。
- `Series` は `放浪記` のまま（話数順の並びを保つため）。表示名の英訳はサイト側で行う。
- `Tags` は**既存の日本語タグ値をそのまま流用**する。新しい英語タグ選択肢を作らない
  （DBが汚れる）。英語ラベルへの変換は表示層の責務で、対応表は `reference/output-spec.md`。
- `Status` は人間承認まで `Draft`、承認後に `Published`。
- `WP ID` / `WP URL` は英語版では空。

### 4-3. 配信先は「英語版サイト」（日本語サイトの言語切替ではない）

英訳記事は**Q-siteの英語版サイト**に配置する。日本語サイトに英語記事を混ぜたり、
記事単位の言語トグルを付けたりはしない。

- 英語版サイトのコンテンツは **`Lang = EN` のページのみ**。日本語ページは一切出さない。
- 英語版サイトに載るのは **放浪記の全訳＋運営者本人が選んだ個人記事いくつか**であり、
  日本語サイトの全記事ミラーではない。掲載対象は `Lang = EN` の存在で決まる。
- したがって放浪記以外の記事も英訳対象になりうる。その場合も本スキルの4パスと
  `voice-bible.md` をそのまま適用する（シリーズ固有の用語だけ `glossary.md` に追加）。
- スラッグは日本語版と衝突させない。英語版サイトが別ルート・別デプロイのどちらになっても
  安全なようにしておく。

> **前提作業（本スキルの範囲外・別タスク）**：`Lang` プロパティの新設、英語版サイトの構築、
> `sync-notion.mjs` の `Lang` 対応。翻訳と並行して進める必要がある。

### 4-4. 会員限定マーカー（絶対に壊さない）

日本語版の本文中には次のブロックがある：

```
<callout icon="🔒">ここから会員限定</callout>
（以下内容転載禁止、法的対処有。）
```

英語版でも**同じ段落位置**に置く：

```
<callout icon="🔒">Members only from here</callout>
(Reproduction of the content below is prohibited. Legal action will be taken.)
```

位置がずれると**有料コンテンツが無料で露出する**。機械QAで必ず検証する。

### 4-5. タイトルとスラッグ

- タイトル：`The Vagabond Chronicles #103 — Finding Goa, Part 6`
  （`#` は3桁ゼロ埋めしない素の数字。アーク名の英訳は `reference/arc-map.md` に固定）
- スラッグ：`<英語タイトルのkebab>-vagabond-chronicles-<NNN>`
  例：`finding-goa-6-vagabond-chronicles-103`
  日本語版スラッグと衝突しないこと（サイトは `/posts/<slug>` でルーティングする）。
- Excerpt：**489本は日本語版も空**なので、英語版は新規に書く。30〜50語、
  固有名詞と具体的な場面を含める。あらすじではなく「読みたくなる引き」にする。

## 5. ユーザーへの提出物（英語を読まずに検証できる形）

**ユーザーは英語の自然さを判定しない。** したがって：

### 5-1. 分担の明示

| 判定項目 | 担当 |
|---|---|
| 英語として自然か・訳文くさくないか | **Claude**（パス③のゲートで担保） |
| 事実・固有名詞・出来事が原文どおりか | **ユーザー**（日本語の逆翻訳で検証） |
| 声・キャラクターが本人らしいか | **ユーザー**（日本語の判断メモで検証） |
| 会員限定の境界位置 | 機械QA＋ユーザー確認 |

### 5-2. アーク完了ごとに出す日本語レポート

```markdown
## アーク「ゴアに出会う話」（Ep 98–117）英訳完了レポート

### 1. 逆翻訳（英語版を日本語に戻したもの）
Ep 103 について、英訳を白紙状態から日本語へ戻した文章：
（※原文を見ずに英訳だけから日本語化しているので、ここが原文と食い違えば意味のズレ）
...

### 2. 訳出で判断が必要だった箇所
| 原文 | 英訳 | 判断理由 |
|---|---|---|
| チロム | chillum | インドの喫煙具。初出で "a chillum, the conical clay pipe" と短く説明を添えた |
| 五度目の正直 | fifth time lucky | 「三度目の正直」の英語慣用は "third time lucky"。数字を変えた言い回しで笑いを保った |

### 3. 意図的に原文から離した箇所（と理由）
...

### 4. 英語品質ゲートの結果
ブラインド査読 2周でP1ゼロ。機械QA 全項目パス。
```

**逆翻訳は必ず「英訳だけを見て」行う**。原文を見ながら戻すと原文に引きずられ、検証にならない。

## 6. アーク単位の運用

`reference/arc-map.md` に全47アークの区間・英題・あらすじを定義済み。

- **1アークを1バッチ**として処理する。アークをまたいで話を分断しない。
- 各話の翻訳時に**アーク文脈カード**を渡す：登場人物（英語表記込み）・現在地・前話までの出来事・
  そのアーク特有の用語。これがないと人物名や地名の表記が揺れる。
- アーク完了時に**通し読み整合パス**：人名・地名の表記統一、時制の一貫性、
  繰り返し表現の重複（同じ比喩を5回使っていないか）をチェックする。

## 7. 品質が蓄積する仕組み（これが無いと522話ずっと同じ品質）

**ユーザーからの指摘、③で繰り返し出る指摘は、その記事だけ直して終わりにしない。**

- 訳語の指摘 → `reference/glossary.md` に追記
- 言い回し・リズムの指摘 → `reference/voice-bible.md` に Before/After として追記
- 繰り返し出る translationese → `reference/translationese.md` に追記し、機械QAの検出語に加える

この書き戻しを毎アーク必ず行う。これがあれば100話目には別物の品質になる。

## 9. 着手前にユーザーへ確認すること

1. `Lang` プロパティの新設と、サイト側の英語ルーティングを誰がいつやるか。
2. 会員限定記事の英語版も同じ課金対象にするか（無料公開にするなら 4-4 の扱いが変わる）。
3. 公開ペース（アーク単位で随時公開 / 全訳完了後に一括公開）。
4. 放浪記以外に英語版サイトへ載せる「個人記事」がどれか（英訳対象の確定）。
